## 正文（可以直接发）

最近一直在做一个自己确实想用的演示工具，叫 **MindDeck**。

项目是开源的：

- 在线首页：https://18611429192.github.io/minddeck/
- 直接看 Demo：https://18611429192.github.io/minddeck/demo.html
- GitHub：https://github.com/18611429192/minddeck

做它的原因其实很简单。

平时做技术方案、产品方案或者项目汇报时，我经常先画一个思维导图，把整件事理清楚。真正开始做 PPT 以后，又要把这棵树拆成几十张线性页面。

拆完以后有两个问题一直让我觉得别扭：

1. 页数多了以后，很难再看见整个内容的结构。
2. 真正汇报时，现场经常不会严格按准备好的顺序走。

比如我准备了这样一段：

```text
用户问题
└─ 安全
   ├─ 权限
   ├─ 数据
   └─ 审计
```

正常情况下，我可能只想讲“安全”这一页结论。

如果现场没人追问，权限 / 数据 / 审计都没必要讲；但如果有人突然问“权限到底怎么设计的”，我又希望可以直接展开这个分支继续讲，而不是退出演示去找备用页。

所以 MindDeck 的基本想法是：

**思维导图一直保留为演示结构，每一个节点内部再放一张真正的 16:9 页面。**

演示时，当前展开的节点决定真正的播放序列。把一个分支收起来，它下面的页面就暂时离开序列；重新展开，又可以继续讲。

目前已经能做的东西包括：

- 多种思维导图布局、曲线连线、节点拖动和折叠
- 每个节点独立 16:9 页面
- 文字 / 图片 / 视频 / 形状
- 母版
- 简单元素动画
- 页面多选、对齐、图层
- 演示目录
- 演示过程中动态展开 / 收起分支
- 鼠标滚轮、方向键、手机滑动翻页
- JSON / `.minddeck` / 独立 HTML / 融合 HTML 导出
- 桌面和手机适配

最近还专门做了一份 Showcase Demo，不用安装，可以直接打开：

https://18611429192.github.io/minddeck/demo.html

我现在没有打算继续疯狂堆功能，反而更想把正式汇报时会出问题的地方收拾干净。

所以如果有人愿意试，我最希望得到的反馈是：

- 哪一步让你觉得不符合直觉？
- 哪个地方让你觉得“这个我不敢拿去正式会议用”？
- 你实际做技术方案 / 培训 / 答辩时，有没有这种“主线 + 临时展开细节”的场景？

项目现在还是 RC 阶段，有些地方肯定还比较粗糙。如果刚好有人也觉得“PPT 页面列表不太适合复杂结构”，欢迎试一下。

## 发帖时建议

不要在标题里写“震撼”“下一代”“颠覆 PPT”之类的词，也不用主动求 Star。

首帖最重要的是让人点开 Demo。有人回复具体问题时，就按真实开发者的口吻直接讨论问题；如果对方提出好建议，可以当天开 Issue 或修一个小版本，再回帖告诉他已经改了。这种互动比单纯顶帖有效得多。
