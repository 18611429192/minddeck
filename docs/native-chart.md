# V10 Step 3 — Native Chart Element

MindDeck V10 Step 3 adds `element.type = "chart"` to the existing MindDeck Project element model. It does **not** add a Chart Runtime, Presentation renderer, Portable renderer, second Composer, or second Project model.

The path remains:

`DeckSpec / SlideContent → Core.Composer → MindDeck Project.slideElements → Slide → Element → Editor / Presentation / Portable`

## Project contract

A chart is ordinary JSON project data:

```json
{
  "id": "chart_example",
  "type": "chart",
  "x": 112,
  "y": 292,
  "w": 1280,
  "h": 470,
  "z": 1003,
  "chartType": "line",
  "categories": ["Q1", "Q2", "Q3"],
  "series": [{"id": "series-1", "name": "Revenue", "values": [12, 18, 27]}],
  "labels": ["Q1", "Q2", "Q3"],
  "values": [12, 18, 27],
  "options": {},
  "style": {}
}
```

No DOM node, canvas context, callback, function, class instance, or runtime object is stored in Project data. Chart normalization rejects non-finite/non-JSON data at validation time and produces deterministic arrays/options.

## Supported chart types

The first native set is fully rendered as SVG primitives:

- `bar`
- `line`
- `area`
- `donut`
- `radar`
- `funnel`
- `waterfall`

These are not placeholders implemented with ordinary `shape` elements. The chart host is an existing Element host and the visual content is generated by the shared Element renderer.

## Runtime ownership

Implementation is under the existing runtime modules:

- `src/runtime/modules/chart-data.js` — schema, normalize, validation, theme-style resolution
- `src/runtime/modules/chart-svg.js` — shared Cartesian SVG helpers and bar/line/area
- `src/runtime/modules/chart-special.js` — donut/radar/funnel/waterfall
- `src/runtime/modules/chart.js` — one native chart renderer and installation into existing `Project.normalizeElement` / `Element.create`

`PresentationView` and `Portable` are unchanged: both still call the same `Slide.render()` and `Element.create()` path.

## Composer

`Core.Composer.normalizeSlideContent()` and `normalizeDeckSpec()` preserve explicit `content.chart` data. `metrics` and `trend` templates compile an explicit chart into one native chart element while retaining the existing page header. Old V9.9/Step-0 samples without `content.chart` keep their frozen text/shape output, so enabling Step 3 does not rewrite the Golden baseline.

## Theme V2

Native charts consume the existing Theme V2 `chartStyle` plus palette/typography tokens. The resolved chart style covers:

- text
- grid / grid color
- series palette
- axis
- background
- emphasis
- font family / labels

No chart-specific theme registry is introduced.

## Editor and Portable

Because a chart remains an ordinary Project element, the current generic editor behavior applies without a chart editor runtime:

- move / resize
- copy / delete
- checkpoint + undo/redo
- save / reload
- Presentation
- Portable export

A full chart property inspector is intentionally not introduced in Step 3; that belongs to the later Slide Inspector work.

## Regression strategy

The V10 Step-0 Golden files stay frozen. Step 3 adds a separate native-chart golden covering a real `metrics` donut and `trend` line. Release checks add `tests/chart.test.mjs` for schema, normalization, serialization, all seven SVG renderers, Composer, Theme V2, generic editor manipulation contracts, Portable preservation, generated Shared Runtime parity, deterministic output, and chart-aware project quality.
